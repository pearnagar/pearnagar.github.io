EPL Moneyball AI

An end-to-end machine-learning pipeline that turns five seasons of historical football data into engineered match features, trains an XGBoost model and combines live inference with bookmaker odds to surface probability gaps.

Pipeline architecture

The project separates historical learning from live inference: historical match data creates the feature space and model, while live odds and fixtures are injected only at prediction time.

The modeling problem

Football is noisy and non-stationary. A useful model has to represent recent form without throwing away longer-term signal, and it must avoid treating raw team statistics as if every opponent or season were equivalent.

01 · RECENCY

Recent matches matter more

Training examples use time-decay weighting so newer seasons have more influence than older matches. The goal is to reflect current team strength without discarding history entirely.

02 · FORM

Turn sequences into features

Rolling averages over recent matches capture momentum in points and goals. Lagged features ensure the model learns from information that would have been available before the fixture.

03 · MATCHUP

Model interactions, not isolated teams

Interaction features compare one side’s attacking strength against the opponent’s defensive weakness, making the feature space matchup-aware rather than team-only.

04 · MARKET CONTEXT

Use odds as another signal

Historical odds are used as market-sentiment features, and live odds are compared with model probabilities at inference time to expose differences between the two views.

Key decisions

The value of the project is in the full data path, not only the classifier choice.

Automated historical ingestion

Each run can retrieve multiple seasons from football-data.co.uk, reducing dependence on a manually prepared local dataset and making the notebook easier to reproduce.

Secrets stay outside the notebook

The Odds API key is designed to live in Google Colab Secrets rather than in source control, keeping live integrations separate from published code.

Explicit probability threshold

The value-detection rule only flags a gap when the model probability exceeds the implied market probability by more than five percentage points.

Evaluation

The repository reports model metrics on unseen test data and keeps match-winner classification separate from total-goals error.

Match outcome

The XGBoost classifier reports 54.08% accuracy on the unseen test set for Home / Draw / Away prediction.

Total goals

The goals model reports a mean absolute error of 1.31. That gives a separate error measure for the regression side instead of hiding it inside one headline metric.

What I would improve next

The next iteration would focus less on adding features and more on making the evaluation harder to fool.

Time-series validation & calibration

Replace a single train/test view with rolling time-based validation and measure probability calibration with metrics such as Brier score and reliability curves.

Experiment tracking & leakage guards

Track feature sets, model versions and metrics across runs, and add explicit automated checks that every live feature is available strictly before kickoff.
